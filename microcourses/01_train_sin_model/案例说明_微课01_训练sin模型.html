1这个方案到底在做什么

一句话：教一个只有 4353 个参数的小神经网络去认一条正弦曲线，然后把训练好的网络导出成 .onnx，为后面"塞进 ESP32-S3 芯片里跑"做准备。

为什么要先做这个"玩具题"？因为真实端侧部署的完整链路是 训练 → 导出 → 量化 → 上板。这条链路上每一步都可能出错，而 sin 曲线是最便宜、最可控的练习题：没有数据集要下、CPU 十几秒跑完、对错一眼能看出来。它相当于整套课程的"hello world"。

三个概念先对齐

名词是什么在这个案例里的角色
PyTorch训练框架写网络结构、跑训练、存权重
ONNX模型交换格式（一个文件）PyTorch 和乐鑫工具链之间的"通用语"
ESP-DL / PPQ乐鑫的端侧推理库 + 量化工具下一课（微课 02）才登场

记不住没关系，只要知道：本课只做到"导出 ONNX"这一步为止。

2怎么实现的（逐步拆解）

1造数据在 x∈[0,2π] 上取 1000 个点，y = sin(x) + 0.05×随机噪声
2搭网络1→64→64→1 的 MLP，前两层后接 ReLU
3训练Adam(lr=1e-4) + MSE 损失，跑 500 轮
4导出转成 opset 12 的 ONNX，batch=1、静态 shape

2.1 网络结构：三层全连接

输入 x (1维)
  └─ fc1: 1  → 64   然后 ReLU     ← 1×64 + 64   =  128 个参数
  └─ fc2: 64 → 64   然后 ReLU     ← 64×64 + 64  = 4160 个参数
  └─ fc3: 64 → 1    不接激活      ← 64×1 + 1    =   65 个参数
输出 y (1维)                          合计 4353 个参数

为什么最后一层不接 ReLU？因为 ReLU 会把负数压成 0，而 sin(x) 的值域是 [-1, 1]——有负数。最后一层要是接了 ReLU，网络永远输出不了负值，曲线下半部分就废了。这是新手最容易踩的直觉坑。

2.2 训练配置（每一项都从源码回读过）

项目取值说明
样本数100080/20 划分 → 训练 800 / 验证 200
批大小32800 ÷ 32 = 25 个 batch
优化器Adam, lr=1e-4学习率偏小，但配合 500 轮足够
损失函数MSELoss回归任务的标准选择
轮数500CPU 上约 13 秒
随机种子42固定数据划分
噪声强度0.05y = sin(x) + 0.05×randn()

2.3 导出 ONNX 的关键约束

  • opset 12 —— 乐鑫工具链要求的版本，太高会不认。
  • batch=1 + 静态 shape —— 端侧芯片一次只推理一张图，不能有动态维度。
  • dynamo=False —— 走传统导出路径，兼容性更稳。
  • 导出后再跑一遍 onnxsim 简化，最后用 onnx.checker 校验合法性。

4遇到的问题（真实踩坑记录）

坑 1 ｜ 终端搞混，报"找不到环境"

现象

执行 conda activate torch_gpu 报 EnvironmentNameNotFound: Could not find conda environment: torch_gpu，但环境明明装了。

根因：这台机器上有两套互不相通的 conda——一套在 Windows 侧（Anaconda Prompt），一套在 WSL/Ubuntu 侧。课程环境在 Windows 侧，而当时开的是 Ubuntu 终端。

怎么判断：看提示符。出现 k@DESKTOP-XXXX:~$ 就是 Ubuntu；(esp32s3) C:\Users\user\...> 才是 Anaconda Prompt。

万能兜底：不激活环境，直接用全路径，任何终端都能跑：

"C:\Users\user\anaconda3\envs\esp32s3\python.exe" sin_model.py --epochs 500 --seed 42

坑 2 ｜ 老师 README 的命令在 cmd 里全是错的

现象

README 里写 wget、ls、test -f、head -4，在 Anaconda Prompt 里逐条报"不是内部或外部命令"。

根因：README 是 bash 语法（Linux/macOS），用户用的是 cmd（Windows）。这不是用户操作错，是文档没做平台适配。

老师写的（bash）cmd 里要换成
ls Xdir X
test -f Xdir X
cat Xtype X
head -4 Xpython -c "print(open('X').read())"
wget -O f URLcurl -L -C - -o f URL
unzip ftar -xf f
行尾 \ 续行行尾 ^ 续行

坑 3 ｜ 照 README 装依赖，会悄悄降级 setuptools

现象（用 dry-run 预演抓到的，实际没执行） 
Collecting setuptools<82 (from torch==2.11.0 -> requirements.txt (line 3))
Would install setuptools-81.0.0

根因：环境里 setuptools 是 83.0.0，而 torch==2.11.0 声明要求 setuptools<82。所以"装依赖"这个动作唯一的效果就是把 setuptools 降级，其余 6 个包全是"already satisfied"。

为什么危险：降级 = 先卸载再安装。这台机器的安全策略会拦截批量删除，包容易被删成"半残"（元数据还在、代码没了，pip 还以为装好了）。

怎么处理：直接跳过（setuptools 只是打包工具，torch 运行时根本不 import 它，降级对课程零收益）。真要"照步骤走一遍"，加 --no-deps：

python -m pip install --no-deps -r ..\01_train_sin_model\requirements.txt
养成的好习惯

动 pip 之前先跑 pip install --dry-run -r <文件> 预演，看输出里有没有 Would install / Would uninstall。这是零风险的核实方式——不靠嘴说"危险"，让 pip 自己说。

坑 4 ｜ 以为"设了 seed 就一定一样"

一开始的误解

以为手写版和老师版用同一个 seed 42，训练轨迹就该完全一致。

实际情况：两个脚本第 1 轮 loss 就不同（0.389344 vs 0.451630）。原因是随机数的消耗路径不一样：老师脚本用全局随机数给 DataLoader 打乱数据，手写版用独立的 Generator——同样的 seed，喂给了不同的地方，结果自然不同。

正确的说法：手写版的三套产物逐字节一致，只能证明手写版自身可复现，不能证明"和老师等价"。

坑 5 ｜ 拿 PNG 当"完全一致"的证据

现象

同样数据跑出来的 loss_curve.png，肉眼一模一样，但 MD5 不同。

根因：PNG 文件里内嵌了 matplotlib 的版本号等元数据，环境一变，文件字节就变。图像文件不能作为逐字节证据。

结论：只有数值产物（.csv / .onnx / .pth）才算数。

坑 6 ｜ 报错是"套娃"的，第一层报错不是根本原因

现象

跑 1.py 时终端刷出一串报错，最上面那条看着像"文件找不到"。

真相：真正的原因在最下面一条。Python 的报错栈是从外到内的，最后一行才是根本原因，上面全是"我在调用谁"的路径记录。新手常被最上面那条误导。

坑 7 ｜ 数字凭记忆写，写错了四次

踩过的具体错误
  • 把学习率写成 1e-3（实际是 1e-4）
  • 把噪声写成 0.02（实际是 0.05）
  • 把轮数写成 5000（实际是 500）
  • 把 4353 个参数错记成"老师脚本的特征"（其实是网络结构本身的）

定下的规矩：凡是要写进交付物的数字，必须先打开源码确认或实跑一遍。不许凭记忆、不许"应该差不多"。

5这一课收获了什么

  1. 跑通了端侧 AI 的第一段链路：训练 → 导出 ONNX。这是后面所有案例的地基。
  2. 理解了"参数量"从哪来：每一层的 输入×输出 + 偏置，加总 4353。不再是玄学。
  3. 知道了激活函数不能乱接：最后一层接 ReLU 会导致输出永远非负，直接废掉。
  4. 学会了两个保命习惯：动 pip 前先 dry-run 预演；写数字前先回读源码。
  5. 认清了"seed ≠ 完全可复现"：这个认知在后面扩展案例 1 里会被彻底验证（同一台机器跑两次结果都不同）。
